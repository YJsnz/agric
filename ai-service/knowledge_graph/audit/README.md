# 第一阶段验收与修正（2026-09-15）

## 结论

数据库存储、本体分类、基本检索、关系证据追溯和 FastAPI 链路已实现并实测。
完整的“泊头本地黑星病防治与采后腐烂风险决策”尚不具备充分的本地证据；不能把工程验收通过说成农业知识已全面验证。

## 真实数据链路

浏览器 8090 → FastAPI `/api/graph`、`/api/paths`、`/api/ask` → `server.query_database` → Neo4j HTTP 事务接口。
数据集为 `pear_evidence_v2`。数据库由 Compose `neo4j-data` 命名卷持久化于容器 `/data`。
构建 JSON 是可重建的入库资料，不是页面运行时数据源。数据库失败返回错误，无 JSON 回退。
`/openapi.json` 和 `/docs` 提供 FastAPI 接口定义。8081 仍是整个项目主入口。

## 修正内容

- 区分作物与品种、农事操作与技术要求、生育阶段与其他生产阶段、环境因素与储藏条件、采收操作、防控措施、品质指标与采后风险。杜梨砧木等没有冒充品种。
- 保留稳定 ID，更新真正的 Neo4j 标签及 `type` 属性。防控措施附加 `Intervention` 父标签，采收操作附加 `AgriculturalPractice` 父标签。
- 节点补充 `description`、`crop`、`region`、`source_count`、`source_ids`。其中地区、作物是关联条目的汇总，不能当作节点整体在所有地区有效。
- `LOCATED_IN` 取代产地关系旧名；补充有原文支持的发生过程、管理目标、监测建议和开花期农事适用关系。
- 更正农业农村部文献条款定位；不改变国外资料 `transfer_pending` 状态。
- 所有农业关系均保留证据 ID、条款位置、适用条件、地区、作物、阶段及证据等级。阶段未确定时保留空列表，不擅自标为全阶段。
- 不填写虚构概率；JSON 中置信度为空，Neo4j 不存储 null 属性。未有证据的 `INHIBITS`、`AFFECTS`、`REDUCES_RISK` 保留在本体中，不为满足类型数量造边。
- 同步网页类型名称、筛选项、作物/品种兼容、布局和推荐分类。

## 七类问题的验收解释

| 问题 | 能力与限制 |
| --- | --- |
| 黑星病是什么 | 以规范名称“梨黑星病”及别名“黑星病”检索，含病原与描述；参考资料为异地梨指南 |
| 有什么症状 | 可查症状边和原始来源 |
| 什么因素促进发生 | 通过明确的发生过程边查到持续湿润及其条件；不把湿润等同于空气高湿 |
| 有什么防治措施 | 可查初侵染预防目标、温湿条件监测；不提供未核对本地登记的用药剂量 |
| 与哪些品质风险有关 | 可查果实畸形、病斑等已收录表现；不把这些表现自动等价为腐烂 |
| 有无生产到采后路径 | 采收牵拉果梗→梗基腐烂风险；黑星病→采前晚期感染→储藏显症。后者为异地参考，属于事实/关联路径 |
| 重要关系出自哪里 | 每条关系指向来源记录及章节；知识记录通过 SUPPORTED_BY 关联 Source |

“持续湿润→采后腐烂风险”查询应返回空，这是证据边界验收，不是系统故障。
严格选“泊头市”时不得显示国外黑星病防治为本地结论。需继续补充本地农技原文及专家审核，才能完成本地场景知识验收。

## 复现

在项目根目录执行：

```powershell
py -3 -m unittest discover -s ai-service/knowledge_graph/tests -p test_v2.py
py -3 ai-service/knowledge_graph/audit_live.py
```

`live-results.json` 是直接查询 Neo4j 得到的验收结果、数量、关系类型、示例问答及证据，不是手工填写的通过报告。
`acceptance.cypher` 可复制到 http://localhost:7474 手动执行；查询限制当前数据集，并区分农业路径与溯源边。
`test_dashboard.mjs` 使用 Edge CDP 9229 检查真实页面的按钮、筛选、路径、聊天、导出与移动布局。

启动 FastAPI：在 `ai-service/.venv` 安装 `graph_web/requirements.txt`，然后运行 `ai-service/graph_web/start.ps1`。
现有问图谱是确定性证据检索，不是完整 GraphRAG、结构因果模型或反事实效果估计。
