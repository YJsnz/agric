# 农业 GraphRAG 主链路修复 V2

## 当前主链路

`/api/graphrag/ask` → 问题用途路由 → 实体抽取与逐字词表补全 → 实体对齐 → 双路候选 → 证据准入 → BGE全候选评分 → 排名融合Top5 → DeepSeek → 引用规范化 → 模型辅助证据核查 → 发布。

`/api/graphrag/rerank`也使用同一准入与排名模块。`/dual`与`/search`仍是显式参数控制的研究诊断接口，其结果不是已核查的生产建议。

## 已修复

1. **用途不同，准入不同**：明确论文阅读按标题限定来源，不把文中试验所在地、生育期当作用户田块的条件。当地生产建议采用严格匹配；缺少作物或所在地会追问。一般知识允许未知范围进入候选，但附带范围警告；明确冲突仍排除。带论文标题的本地应用问题仍走当地建议策略。
2. **阶段与路径**：对“贮藏/储藏”“开花期/花期”等保守归一；不把“采后”等同储藏或货架期。检索可以发现其他阶段邻居，但发布前逐路径验证阶段。没有阶段标注的分类导航仅用于找到实体，不证明当前阶段发生病害。
3. **实体入口**：新增虫害、症状、品质/指标、措施、采后风险；使用图谱既有名称与别名补齐问题中逐字出现的实体。LLM抽取失败时保留明确提示，采用词表回退，不能猜测未知地区、病害或阶段。
4. **图谱导航**：增加HAS_DISEASE、HAS_PEST、HAS_DISORDER等事实关系；这些关系不升级成因果。路径遍历有状态数量上限；种子过多时优先具体实体。
5. **融合实际进入问答**：先准入，再BGE重排，最后合并重排名次、向量名次和有界的适用性/证据质量调整。不同分数不直接当概率相加。无强制图谱配额。默认参数未在独立验证集调优，`calibrated=false`。
6. **引用与回答核查**：将正文已存在的E1、【E1】、[E1,E2]、[E1][E2]规范化，不生成不存在的引用，不接受未知编号。引用列表由明确正文标记建立；正文完全没有位置时不能自动补造。随后逐字段核查实际引用的证据。最多一次有反馈的修订；仍未通过则不发布草稿，返回`validation_failed`，区别于`insufficient_evidence`。

## 跨阶段注释契约

只有证据核查后的边同时具备以下注释，才允许把当前路径阶段推进到结果阶段：

- `from_stage`、`to_stage`：必须可解析为图谱中已有的Stage/GrowthStage，且都在该边`stage_ids`中。
- `transition_evidence_ids`：必须是该边已读来源`evidence_ids`的子集。
- `transition_locator`：明确指向原始材料中描述阶段转换的条款或段落。
- `review_status`：`source_checked`或`local_expert_reviewed`。

后续边需匹配推进后的阶段。只有`stage_ids`含两个阶段，并不证明有从前者到后者的转换。此次没有为满足测试新增任何无来源的农业边。当前资料若没有这种注释，相关路径仍可能因证据不足被拒绝；这是知识补充任务，不能用放开阶段过滤代替。

## 测试与运行

从agric目录运行：

```powershell
ai-service/.venv/Scripts/python.exe -m unittest discover -s ai-service/scripts -p 'test_graphrag_v2.py'
ai-service/.venv/Scripts/python.exe -u ai-service/scripts/graphrag_v2_smoke.py
```

真实验收访问8090接口，需要本机Neo4j、BGE及已有DeepSeek配置。验收记录保存到`data/botou_yali/evaluation/graphrag_v2_repair/`，复验前一份记录归档到`history/`。

## 不应混淆

- 模型辅助核查不是形式化蕴含证明或农业专家审定，可能误判。
- 证据等级不是因果效应强度；没有新增损耗百分比、置信度或反事实模型。
- 功能验收不等于baseline准确率。旧`baseline_v1`保留原结果，不能覆盖或把4个验收问题当作独立测试集。新算法的比较实验需另建版本目录、记录改动并保留失败项。
- 当前图谱资料覆盖不足仍可能使某些论文题没有图路径；不能强行匹配不相关关系来提升“图谱参与率”。
