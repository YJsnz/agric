## 1 系统范围与架构

平台由React官网、Vue主工作台、独立多作物前端、Spring Boot业务服务、官方Harness运行时、Python视觉与知识服务以及MySQL和Neo4j组成。浏览器经Java统一鉴权访问业务和多作物代理接口；Three.js在客户端渲染场景，后端负责记录和权威运输状态。

| 组件 | 当前技术 | 责任 |
| --- | --- | --- |
| 官网 | React 18与Vite | 品牌介绍 注册 登录 |
| 主工作台 | Vue 3 TypeScript Three.js 0.152.2 | Agent 数据 作物 2D与3D |
| 业务服务 | Java 17 Spring Boot 4.1.0 JPA | 鉴权 数据 任务 记录 运输 |
| Agent运行时 | DeepSeek Harness SDK 0.2.0-rc.2 | 工具循环与会话事件 |
| AI服务 | Python FastAPI ONNX Runtime Ultralytics | 视觉与知识检索 |
| 存储 | MySQL Neo4j 文件目录 | 业务状态 图谱 原图与模型 |

一次视觉知识任务的路径为：地块选择→确定作物和识别任务→上传或摄像头采样→Java鉴权代理→对应Python模型→视觉候选→知识实体匹配→图谱问题预填或循证问答。模型识别标签只是一条观察线索，不能跳过知识证据准入与人工复核。

运输路径为：设施侧栏打开导航弹窗→选择取送点与货物→合法路线预览→库存预留→车辆取货→确认或自动装货→交付→入库流水。2D和3D只是同一任务的两个显示端。当前运输账和采后批次账独立，尚无自动创建采后批次的桥接逻辑。

## 2 数据模型与接口

MySQL保存用户、农场资产、环境观测、告警、个人面板、Agent任务与事件、视觉任务与复核、业务记录和运输状态。Neo4j保存作物知识实体及带来源的关系。上传原图和模型文件位于文件系统，不由浏览器自行覆盖。

## 3 Agent内核与资源控制

默认使用官方Harness sdk-minimal profile，自有Java循环保留为legacy兼容路径。Java管理身份、基地上下文、任务队列和结果核验，Node子进程运行SDK。系统禁用shell工具，只注册农业白名单插件：get_farm_context、analyze_environment、retrieve_evidence、get_vision_records、get_business_records及query_crop_knowledge。工具执行仍由后端权限和参数校验约束。

任务按创建、排队、运行、完成或失败/取消管理，工具调用与结果保存为有序事件。重试创建关联任务，不声称从模型内部中断状态恢复；取消会回收子进程。最终答案先核对要求的工具是否实际调用，以及指定视觉记录和业务批次是否一致，缺失事实使用保存结果摘要纠正。

## 5 多作物视觉识别

模型由地块作物和识别对象选择。梨包括公开叶片检测及分支症状分类；麦包括叶部类别、水分胁迫和麦穗检测；枣包括叶部、碰伤和新鲜度。本轮从多作物分支提取番茄叶片分类与果实成熟度两份冻结V1权重，接入主工作台视觉组件、Java路径白名单和统一Python服务。独立多作物页的设施蔬菜入口仍以知识服务为主；其旧版健康字段不能代替番茄专用健康接口。

## 8 道路约束与全局导航

## 11 Windows构建与启动

源码环境要求JDK 17及以上、Node 24及以上、Python 3.11、Docker Desktop和兼容模型服务。start.cmd调用scripts/main.ps1，读取未跟踪的.env.local，初始化数据库，安装Agent、视觉与多作物依赖，构建landing、frontend、vision-frontend，再启动Spring Boot。已经安装依赖时可使用-SkipBuild，不能把它用于全新安装。

当前MySQL展示容器为agric-mysql，映射3307；不要默认连接其他项目的3306数据库。Neo4j默认本机7474，多作物Python默认127.0.0.1:8090，Java主程序8081。端口、密码、JWT密钥和模型地址由私有配置提供，文档不携带真实凭据。

MultiCropRuntime在应用就绪及请求前检查本机服务，15秒监督一次，子进程退出后按冷却时间重启。仅管理本机HTTP配置，远程地址复用不拉起本地进程。默认Neo4j容器存在且停止时可docker start；首次容器创建与知识初始化仍由setup-multicrop负责，监督器不替代首次安装。

知识页面使用有上限重试，约75秒总预算，切换作物或卸载页面取消旧请求。401/403/404等不作无限重试。运行诊断必须同时检查Java、数据库、配置模型、权重、Neo4j及Python，不能用/api/health的UP替代整个系统健康。

构建顺序为三个前端npm ci与npm run build，再mvnw.cmd test和mvnw.cmd package。scripts/create-release.ps1与scripts/create-jetson-release.ps1复制指定JAR，默认不重建，也默认不包含多作物；完整包必须加-IncludeMultiCrop并检查模型与图谱数据。审计时已有JAR仍是10月12日版本，不能当作本技术基线最新包。

## 14 运维安全与演进

商业发行要整理原软件、公开权重、训练样本和生成素材的来源与许可，包含梨叶上游和Ultralytics AGPL相关文件。文档中的许可说明是工程清单，不替代对具体发行形式的审查。无需真实硬件展示并不意味着可以省略软件依赖与许可证交付。

## 15 串口设备通信与数据入库

TY Serial v1面向自研固件，包含CRC16帧、Python持久化网关、C编解码器和模拟固件。默认115200 8N1，载荷不超过2048字节，帧类型为遥测、指令、回执及预留HELLO。真实设备的电气接口和厂家协议仍需确认。

遥测经过SQLite离线缓存、消息去重、指标与采样时间校验后，事务写入farm_observations；来源为serial与设备ID。指令使用requestId幂等创建，网关2秒重试、最多3次，60秒过期；收到成功回执后才更新设备状态。接口仍沿用JWT与共享基地授权口径。

支持采样、自检、开关、档位和停止，设备端需实现定时关闭、最大运行时间与看门狗。完整报文、单位范围、配置与联调说明见[串口接入文档](../embedded/README.md)。现有厂家Modbus或私有寄存器协议、固件烧录和实机串口联调未完成。

批次“演示批次 鸭梨 20261015 A01”登记1200 kg，关联鸭梨一号园，按采收、分选、入库和出库顺序写入事件。界面显示批次编号、二维码、阶段和登记说明。数量、分级和库温为模拟录入，二维码目标需要登录并能访问当前服务，出库记录不代表真实销售。
