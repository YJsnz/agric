# agric 改造为盐田丰语的完整实施方案

版本：V1.0  
编制日期：2026 年 10 月 1 日  
适用范围：现有 agric 仓库、Windows 本地开发和比赛演示。本文是实施设计，新增能力尚未实现；阶段耗时为规划估算。

## 1. 项目目标与交付范围

沿用现有 Spring Boot、Vue 工作台、Three.js 场景和 React 官网，将田言耕智升级为面向沧州盐碱地特色作物的盐田丰语。首个交付围绕泊头鸭梨，完成地块观测、视觉诊断、证据检索、Agent 编排、风险分析、干预推演和采后批次追溯。

AI 工程以 DeepSeek Harness 为主要参考，研究执行循环、插件边界、会话状态、工具协议和前端交互。Qwen2.5 为报告指定的本地模型基线，模型适配层允许后续比较其他模型。业务事实和风险数值由服务返回，模型负责理解任务、选择工具和组织解释。

范围分为两个交付：

| 交付 | 必须完成 | 完成标准 |
|---|---|---|
| 核心版 | 农场/地块数据、历史观测、证据库、因果子图、Agent、视觉接口、风险与干预、采后批次、任务 UI、Windows 启动、评测 | 一条鸭梨生产到采后流程真实运行，结果可追溯 |
| 完整版 | 无人机影像分割、人工地块编辑、作物分类、道路与仓库、多目标路径、GIS/3D 联动、数据扩充与算法评测 | 报告所列模块形成软件闭环，每个算法标注实际验证范围 |

旱碱麦、小枣及其他作物通过字典、知识和模型配置扩展。无人车硬件控制另设集成项目；本项目先交付路线建议、模拟位置和接口。

## 3. 总体架构与服务职责

```text
浏览器：Vue Agent/工作台/GIS/3D + React 官网
                   │ 同源 API、Bearer 认证、流式事件
                   ▼
Spring Boot 业务后端与 Agent 网关
  用户/权限/农场/地块/观测/设备/批次/文件/审批/审计
       │ 内部服务认证、授权上下文、request_id
       ├─────────────► Agent Runtime（优先评估 DSH 的 Node/TS 运行时）
       │                  │ 本地模型适配、工具注册、循环、状态、事件
       │                  ├──► Qwen2.5 本地推理服务
       │                  ├──► Java 农业业务工具
       │                  └──► Python FastAPI 算法服务
       │                           检索/视觉/特征/风险/推演/分割/路径
       ▼
MySQL 业务事实与任务事件 │ Neo4j 图谱 │ Qdrant 向量 │ 本地媒体存储
```

此架构是项目设计，并非对 DSH 现有接口的兼容性承诺。浏览器仅访问业务后端；内部 AI 服务不接受浏览器传来的任意用户身份。Java 签发包含用户、农场权限、有效期与运行 ID 的内部授权上下文，工具再次核验对象权限。

MySQL 为业务事实、任务状态和审计的权威来源。图谱和向量索引是可重建的派生数据。初期媒体用受控本地目录和文件记录，存储接口预留对象存储适配；大图像与模型权重不放进关系库。

每种事实确定一个写入服务，AI 运行时不绕过 Java 直接更新设备、批次。任务事件按固定协议写入，不依赖任何上游私有存储结构。

## 4. DeepSeek Harness 参考和复用策略

### 4.1 先做源码与适配验证

固定上游 commit，建立参考能力表，核验源码中的循环、工具、模型适配、会话、取消、异常、插件生命周期以及 UI 数据流。当前已经确认的是插件架构、Web 会话/模型设置能力和 MIT 许可；任务断点语义、多租户隔离与 Qwen 兼容性仍须专项验证。

用独立 spike 完成以下试验：

1. Qwen2.5 通过选定本地推理服务返回真实工具调用，含多轮调用和非法参数场景。
2. 包装 get_plot_context、retrieve_evidence、risk_analyze 三个农业工具。
3. 一次任务先查询，再检索，再计算，产出结构化结果。
4. 输出开始、工具状态、结果和完成事件；中断后能读取已有结果。
5. 验证取消、超时、工具失败、跨用户会话访问和重启后状态。
6. 查明上游组件 UI 技术栈与本项目 Vue 的适配成本。

### 4.2 技术决策门槛

| 方案 | 采用条件 | 代价 |
|---|---|---|
| 直接复用 DSH 核心，新增农业插件和 API 适配 | 接口可隔离、授权可落地、Qwen 调用可靠、状态可接入 | 增加 Node 服务，维护固定上游版本 |
| 选择性复用许可允许的模块 | 完整运行时耦合过深，但局部模块边界清楚 | 维护抽取代码及上游变更记录 |
| 参考设计，实现精简农业 Harness | 前两者无法满足关键验收项 | 自行维护循环、恢复和事件协议 |

优先评估第一种；spike 完成后写 ADR，给出选择、实测证据和失败项。无论选择哪种，前端使用本项目定义的 Agent API，避免上游升级直接改变业务 UI。复用源码保留版权、许可和第三方说明，记录修改位置。上游升级在独立分支通过契约与任务回归后合入。

### 4.3 农业能力组合

注册模型、会话、上下文、证据、视觉、风险、批次、路线和事件展示等能力。初版只暴露农业白名单工具，不给面向农户的 Agent 任意 shell、文件写入或插件安装权限。MCP 作为未来外部工具接口，不是首版必需依赖。

## 5. Agent 执行与状态设计

### 5.1 请求处理

用户输入和附件 → 绑定农场/地块 → 解析任务与约束 → 必要时补充问题 → 生成简要计划 → 校验并执行工具 → 保存观测和检查点 → 判断证据充分性 → 生成结构化 Decision → 验证来源和数值 → 展示结论或请求操作确认。

模型可根据观测调整计划。只读工具可在依赖满足时并行执行；所有有副作用的步骤按明确依赖串行处理。首版单个 Agent 完成任务；多 Agent 作为评测后扩展，避免增加不必要的协调成本。

### 5.2 状态机

Run：QUEUED → RUNNING → WAITING_INPUT / WAITING_APPROVAL → RUNNING → COMPLETED。任意非终态可进入 CANCELLING → CANCELLED；不可恢复异常进入 FAILED。

Step：PENDING → RUNNING → SUCCEEDED / FAILED / SKIPPED。运行状态和浏览器连接分开；关闭标签页不会默认取消服务端任务。

每个运行持久化目标、约束、版本、授权范围、当前步骤、工具结果摘要和证据集合。重启后只读步骤可重试；写入步骤先核查幂等记录和业务状态，再决定继续。不能声称端到端 exactly-once；利用业务幂等与状态核验防止重复动作。

### 5.3 工具控制

每个工具定义 name、version、JSON Schema、permission、effect、timeout、retry_policy、输出 Schema 和审计字段。建议初始配置为最多 12 个模型轮次、任务墙钟 180 秒、同一非法调用最多纠正 2 次，超过后明确结束或转人工；这些值在性能测试后调整。

读取与计算可有限重试；批次创建、设备控制等调用必须携带 idempotency_key。每次审批绑定运行、动作、对象、参数哈希与过期时间；参数改变需重新确认。审批与业务执行之间重新检查权限和状态。

取消停止后续调度，并请求下游中断；若下游不支持中断，忽略迟到结果并记录状态。已经执行的真实设备动作不能通过取消自动撤销。

### 5.4 工具清单

| 工具 | 数据责任方 | 副作用/确认 |
|---|---|---|
| get_plot_context | Java 地块服务 | 只读 |
| get_environment_features | Python 特征服务，读取授权观测 | 只读/计算 |
| get_weather | Java 气象适配 | 只读，标记缓存与预测时间 |
| vision_diagnose | Python 视觉服务 | 计算并持久化检测记录 |
| query_causal_graph | 图谱服务 | 只读，仅参数化查询 |
| graphrag_retrieve | 检索服务 | 只读，按权限和适用域过滤 |
| risk_analyze | Python 风险服务 | 计算并保存版本化风险快照 |
| simulate_intervention | Python 风险服务 | 保存推演，不改变真实设备 |
| propose_postharvest_batch | Agent | 生成草案 |
| create_postharvest_batch | Java 批次服务 | 确认后幂等创建 |
| route_plan | Python 路径服务 | 路线建议 |
| request_device_action | Java 设备服务 | 明确确认，核查回执 |

### 5.5 上下文、记忆与输出

上下文由后端读取，前端提供的文字仅作用户输入。按任务取相关地块、时间范围、子图和证据，设定大小预算，长工具输出存记录并保留可读取引用。任务摘要不能取代原始证据。

短期记忆属于运行；长期记忆只保存用户确认的偏好、审核过的事实和有来源的任务摘要，记录有效期。删除会话与删除农业记录分开处理。

Decision 包含 summary、facts、inferences、risk_result_id、causal_paths、evidence_ids、uncertainties、proposed_actions。引用必须来自本轮授权检索；数值必须与计算结果一致；缺失关键数据返回 insufficient_evidence 或 needs_input。UI 展示执行过程和决策依据，不编造内在思考文本。

## 6. 数据模型与数据治理

| 数据组 | 核心表/对象 | 主要字段 |
|---|---|---|
| 农场与授权 | farms、farm_members | owner、role、权限范围 |
| 地块 | plots、crop_cycles | farm_id、几何、品种、生育期、版本 |
| 环境 | observations、sensor_sources | plot_id、metric、value、unit、observed_at、quality、source_type |
| 农事 | agricultural_events | 地块、操作、剂量/单位、操作者、时间、证据 |
| 文件与视觉 | media_assets、vision_records | 文件哈希、模型版本、类别、框/掩膜、置信度、采集时间 |
| 文档 | knowledge_documents、knowledge_chunks | DOC/Chunk ID、来源、页/节、地域、作物、阶段、审核、版本 |
| 图谱 | entities、relations、evidence mappings | 关系类型、方向、条件、适用范围、证据、审核、版本 |
| Agent | sessions、messages、runs、steps、run_events | 用户、运行状态、序号、检查点、工具结果引用 |
| 决策 | risk_assessments、intervention_scenarios | 数据快照、规则/模型版本、得分、因素、覆盖度 |
| 采后 | batches、batch_events、quality_checks | 来源地块、采收时间、状态、风险快照、流转记录 |
| 空间 | warehouses、road_nodes、road_edges、route_plans | 坐标系、边权、通行状态、路线版本 |
| 审批审计 | action_approvals、operation_audit、idempotency_records | 主体、对象、参数哈希、状态、执行结果 |

观测索引至少包含 plot_id/metric/observed_at；事件使用 run_id/seq 唯一约束；批次事件包含预期状态版本，避免并发越级。大规模数据以后按实际规模决定分区或时序库。

统一单位、时区与坐标系。时间用 UTC 存储，UI 以 Asia/Shanghai 展示。观测记录采集时间和接收时间；迟到、缺测、离群与传感器校准状态均保留。模拟、导入、传感器和人工数据使用明确 source_type，计算输出标记来源与适用范围。

初始化演示数据独立到 demo profile，不混入正式数据与评测集。文档导入保留原件哈希和来源；更新文档生成新版本，旧任务仍可查看当时证据。媒体上传限制大小、类型和解码尺寸，避免任意路径与解压问题。

## 7. GraphRAG 与因果知识图谱

导入流程：资料登记 → 文本/OCR 清洗 → 按章节和语义切块 → 元数据审核 → 实体对齐 → 关系提取 → 关键因果边人工复核 → 向量索引 → 发布知识版本。

第一期采用 Neo4j + Qdrant；关键词检索先使用可维护的文本索引，不立即增加独立搜索集群。向量模型与 reranker 通过农业中文验证集选择，记录版本；不把生成模型直接当默认 embedding 模型。

实体覆盖作物、品种、生育期、症状、病害、温湿度、土壤盐分、措施、品质、采后环节和证据。相关、因果、干预、建议四种关系明确区分。盐碱地适配需补充土壤 EC、pH、检测方法、采样深度和时间；没有这些数据时不生成盐分诊断。

检索流程：任务实体和意图 → 地块适用域 → 候选子图 → 关键词与向量召回 → 适用域过滤 → rerank → 合并证据 → 引用校验。地域扩大回退必须明确展示，不能悄悄把其他作物证据当本地结论。

图谱路径只证明知识结构中的支持关系；路径衰减贡献不表示真实因果效应。所有关键边可点击定位原文。对文档删除/更新建立重索引队列，记录失败和重试，查询只使用已发布的一致版本。

## 8. 视觉、多模态、风险与干预

### 8.1 鸭梨视觉

先盘点可获得图片与标签，再确定病害类别。数据按果园、采集批次或视频分组划分，去除跨集合近重复。独立测试集冻结。训练、验证、测试记录采集条件和类别分布。

上线接口支持图片与已有检测记录；视频作为异步任务。结果记录器官、类别、置信度、框/掩膜、模型版本和局限。不具备分割与器官掩膜时不输出病斑面积比例；低质量图像与低置信度支持拒识。田间病害和采后外观质检分别设模型/任务版本。

### 8.2 环境特征

计算时间窗内高湿持续时长、累计降雨、温度适宜度、墒情异常和视觉出现次数，携带 coverage、missing_count、时间范围、阈值来源与版本。断续采样不能当成完整持续高湿；设置允许间隔，缺失过多则输出不确定。

### 8.3 风险

初版使用版本化专家规则与可校准加权模型。风险输入冻结为快照；计算过程保存因子值、权重、阈值、规则依据和贡献。输出 risk_score 与 low/medium/high 等级、数据覆盖度和证据支持程度；未经标签校准不得将 score 称为损耗概率。

生产风险到采后风险需要独立映射规则，绑定品种、阶段、质量检查与采后环境。缺数据时保留不确定状态，不以零替代未知。

### 8.4 干预推演

动作模板规定可修改因素、取值范围、证据、约束与成本字段。生成基线和情景快照，重算同一风险版本并展示差异。显示“在这些假设下”的结果，避免把降低分数解释成实证减损比例。首版称为基于因果知识约束的干预推演；积累数据后再研究 SCM 因果估计。

## 9. 采后、GIS、分割与运输

批次状态按 CREATED → QUALITY_CHECK → SORTED → PRECOOLED → IN_TRANSIT → STORED → CLOSED 管理。允许异常、退回和报废事件，但必须定义合法转移。批次创建继承来源地块风险快照，后续状态记录操作者、环境、质检、证据和版本。

批次拆分/合并记录父子关系和数量/单位守恒，追溯页显示来源、流转和风险。批次二维码首版用于授权查询，公开分享只暴露允许字段。

空间模块采用统一 plot_id 和 GeoJSON/WGS84 数据契约，GIS 编辑与 Three.js 使用明确坐标转换。普通航拍 RGB 图没有地理配准时只提供图像坐标标注，不能输出真实面积或导航位置。

无人机分割处理正射影像、切片、重叠融合、边界矢量化和人工修正；保留原模型结果及确认版本。作物分类独立执行，允许不确定类别。大图异步处理并限制内存/GPU队列。

道路维护入口、仓库、分选、预冷、充电等节点及可通行边。首版比较 Dijkstra 与 A*，多目标代价统一单位并记录权重。启发函数必须是综合代价的下界，无法保证时使用 h=0 保持正确性。道路关闭触发重规划；无路径明确返回，不穿过不可通行地块。路线与定位模拟明确标识，真实定位和避障留给硬件接口。

## 10. 前端信息架构与展示逻辑

沿用 Vue 平台和现有视觉基础，参考 DSH 的会话与任务交互，在农业场景中统一组件。是否复用上游组件须先核验框架、样式依赖和许可；不预设可以直接复制到 Vue。

一级入口：智能问农、数据工作台、知识图谱。风险中心、采后管理和农场数字化作为工作台业务入口，模型/知识审核/系统配置按角色进入管理页。

| 页面 | 必须交互 |
|---|---|
| 智能问农 | 会话列表、地块选择、附件、流式结果、简要计划、工具记录、取消/重试、证据、确认卡片 |
| 数据工作台 | 当前/历史环境、质量标记、风险图层、设备状态、告警、批次、Agent 侧栏 |
| 知识图谱 | 适用域筛选、因果/相关边区分、路径高亮、边来源与原文 |
| 风险详情 | 数据时间窗、主要因素、计算版本、证据、缺失数据、干预比较 |
| 采后管理 | 批次列表、数字身份证、质检、状态流转、来源风险、追溯与路线 |
| 农场数字化 | 上传进度、分割结果、顶点编辑、拆分/合并、分类确认、发布地块 |
| 系统管理 | 模型连通性、工具能力、知识导入/审核、任务诊断和版本 |

Agent 桌面布局：左侧会话，中间消息与任务过程，右侧地块/证据/结果详情；小屏使用抽屉。视觉上保留农业品牌、清晰字体和低噪声背景。结果卡片采用稳定结构，不能随模型文本任意创建 UI。

工具卡包含用户可读名称、等待/运行/成功/失败状态、耗时、摘要和详情。模型请求期间显示正在生成；实际工具运行才显示对应工具进度。失败显示原因、是否部分完成和可重试范围。简要计划和执行依据由真实任务信息生成，不以虚构长篇思考制造可信感。

共享组件建议：AgentConversation、RunTimeline、ToolResultCard、EvidencePanel、RiskResultCard、InterventionCompare、ActionApprovalCard。场景侧栏和独立问农页共享 store，地块变化作为可见上下文事件，避免静默改变当前任务。

补齐键盘操作、焦点管理、加载/空/错误态、滚动跟随、长列表分页和附件状态。聊天输入先防重复提交，再以 run_id 跟踪；重新连接不重复追加同一事件。

## 11. API 与流式事件契约

以下为拟新增契约，路径在实现时统一到现有 /api 规范。

| 接口 | 方法 | 行为 |
|---|---|---|
| /api/agent/sessions | POST/GET | 创建/列出授权会话 |
| /api/agent/sessions/{id}/messages | GET | 分页读取消息 |
| /api/agent/runs | POST | 幂等创建任务，返回 202 与 run_id |
| /api/agent/runs/{id} | GET | 状态、结果和部分完成情况 |
| /api/agent/runs/{id}/events?after_seq=N | GET | SSE 事件与回放 |
| /api/agent/runs/{id}/cancel | POST | 取消调度 |
| /api/agent/runs/{id}/input | POST | 补充任务缺失信息 |
| /api/agent/approvals/{id}/decision | POST | 确认/拒绝指定动作 |
| /api/plots/{id}/observations | GET/POST | 历史读取与授权采集 |
| /api/vision/jobs | POST/GET | 创建/查询视觉任务 |
| /api/knowledge/documents、/imports | GET/POST | 资料与异步导入 |
| /api/graph/causal-path | POST | 获取适用子图 |
| /api/risk/analyze、/simulate | POST | 风险与情景计算 |
| /api/postharvest/batches | POST/GET | 创建/读取批次 |
| /api/postharvest/batches/{id}/transitions | POST | 乐观锁状态转移 |
| /api/farm/segmentation-jobs | POST/GET | 地块分割任务 |
| /api/route/plan | POST | 路径方案 |

事件类型：run.created、run.started、plan.updated、step.started、tool.started、tool.completed、tool.failed、answer.delta、evidence.available、approval.required、input.required、run.completed、run.failed、run.cancelled。

事件 envelope：schema_version、event_id、run_id、seq、type、timestamp、payload。响应元数据包含 request_id、数据/模型/规则版本；工具结果包含输入快照引用与证据 ID。事件先持久化再发布，客户端按 seq 去重，断线按 after_seq 补齐。日志和回放不返回密钥或无权限数据。

当前前端使用 Bearer token，SSE 采用 fetch 流式读取以携带 Authorization；如果改用 EventSource，必须配套同源 Cookie 认证和 CSRF 设计，不把 JWT 放进 URL。应用流与事件回放分别处理，运行完成后关闭连接，保留查询 API。

## 12. 权限、可靠性与可观测性

新增角色：农场管理员、操作员、农技审核员、查看者。所有地块、文件、会话、事件和批次按 farm membership 进行对象级检查；当前登录拦截器仅验证登录，必须补充这一层。

检索资料和上传文件作为数据处理，不允许其中指令改变工具权限。只提供参数化图查询和预注册工具，模型不能提交任意 Cypher/SQL。证据服务按用户范围过滤；任务绑定原始权限并在执行时复查。

后台任务采用持久队列记录、租约与心跳，单机初期可在数据库实现。增加 GPU 并发限额、请求预算、超时和熔断。模型不可用时保留查看、确定性业务与历史结果；模型在线结果和离线回放明确区分。

记录 request_id/run_id/step_id、工具耗时、模型用量、队列等待、重试和故障；结构化日志不采集原始密钥，敏感参数脱敏。工具结果与操作审计分开存储，任务 Trace 记录外部可核验的执行过程。

定期备份 MySQL、发布知识版本和媒体，图谱/向量提供重建工具。验收包含恢复备份、索引重建和任务中断恢复。迁移回滚以恢复备份/前版本为依据，避免不可逆变更依赖自动 down migration。

## 13. Windows 开发与部署

| 服务 | 建议本机端口 | 运行方式 |
|---|---|---|
| Java 业务/前端静态资源 | 8081 | Maven 开发启动或 JAR |
| MySQL | 3307 | 已有独立 agric 容器 |
| Agent Runtime | 3081 | 固定版本 Node 服务，仅内部访问 |
| Python 算法服务 | 8001 | 项目 venv，固定依赖 |
| Neo4j | 7475/7688 | Docker Compose，独立数据卷 |
| Qdrant | 6335 | Docker Compose，独立数据卷 |
| 本地模型 | 按推理服务配置，候选 11434 | 首先评估 Windows 本地方案 |

这些是本项目拟定端口，配置可覆盖。统一绑定 loopback，增加 check、start、stop、logs、backup、restore 命令。脚本记录自己启动的进程与 PID，stop 不结束其他项目进程；默认不删数据卷。

start.cmd 支持 Core/Full、SkipBuild、ExternalDatabase、Check、Demo 配置。启动顺序：依赖检查 → 数据服务 → 数据迁移 → 算法服务 → Agent 服务 → Java → 健康探测。必需服务失败停止相应启动并输出定位信息；可选服务失败在能力状态显示降级。

构建使用 npm lockfile、固定 Python 依赖与上游 commit。模型权重和大训练集放 gitignore 下的外部目录，附版本清单与获取说明。为比赛机器预下载模型、镜像和依赖，提供离线安装包清单及完整重启演练。

硬件尚未核验，因此不承诺 Qwen 7B/14B/32B 的显存、速度或并发。P0 检测 GPU、显存、内存和磁盘，并测模型首 token、生成速度、工具成功率与多服务资源竞争；最终配置依据实测。若推理后端需 Linux，采用 WSL2 服务但保留统一 Windows 启动入口。

## 14. 实施阶段与验收门槛

| 阶段 | 交付内容 | 验收门槛 | 估算工程工作量 |
|---|---|---|---|
| P0 基线与 DSH spike | 上游源码核验、Qwen 工具调用、ADR、数据/硬件盘点 | 三工具多步任务、异常测试、复用决定有证据 | 3–5 人日 |
| P1 数据与平台基础 | 迁移、农场权限、地块、历史观测、任务/文件契约 | 对象权限测试、历史特征可复算、demo 隔离 | 5–8 人日 |
| P2 Agent 与交互 | 运行时、工具、状态、事件、问农 UI、取消/审批 | 真正执行、断线回放、写入幂等、越权拒绝 | 8–12 人日 |
| P3 知识与图谱 | 文档导入、混合检索、适用域、因果证据、解释页 | 引用可定位、过期证据可追溯、无证据降级 | 7–12 人日 |
| P4 视觉与风险 | 在线诊断、时序特征、规则版本、干预比较 | 冻结输入可复算，置信度/风险/概率不混用 | 8–15 人日 |
| P5 采后闭环 | 批次、质检、流转、数字身份证、风险继承 | 合法状态转移、来源追溯、确认后创建 | 5–8 人日 |
| P6 空间扩展 | 影像分割、人工编辑、分类、道路、路线、GIS/3D | 几何坐标一致、无路径处理、修正和重规划 | 10–18 人日 |
| P7 固化与评测 | 数据集、消融、性能、Windows 包、文档 | 新机器启动、异常演练、独立评测结果可复现 | 5–8 人日 |

工程总量粗估 51–86 人日，不含资料授权、专家审核、图像采集标注和等待硬件的时间。多人工作可并行，但集成与数据依赖限制缩短程度；单人完成完整范围属于数月级项目。P0 后基于数据和实测重新估算。视觉数据采集与知识审核在 P0 开始，避免等到 P4 才发现无可用数据。

核心版达到 P5 并完成适用的 P7 验收；P6 为完整版扩展。训练模型不足时可以交付平台与模型接口，但该状态不能验收为完整算法版本。

## 15. 测试与评测计划

工程回归保留现有后端测试和双前端构建，补充契约、授权、任务状态、重放、审批幂等、批次状态与关键端到端场景。测试数据库使用独立配置，不共享演示/业务数据。

| 领域 | 评测与记录 |
|---|---|
| Agent | 任务完成、工具成功、非法参数、证据覆盖、耗时、取消、失败恢复 |
| 检索 | Recall@k/MRR、来源命中、引用正确、作物/地域适配、缺证据拒答 |
| GraphRAG | 同一模型/测试集对比直接问答、向量 RAG、图谱检索、混合检索与约束 |
| 视觉 | 独立测试集 Precision/Recall/F1、mAP；分割有对应 mask 标签才评面积 |
| 风险 | 专家等级对照、Macro-F1、加权 Kappa、路径支持；概率模型另做校准 |
| GIS/遥感 | IoU、Boundary F1、分类 Macro-F1、人工修正量、坐标检查 |
| 路径 | Dijkstra/标准 A*/多目标方案代价、时间、路段约束、关闭后重规划 |
| 部署与性能 | 启动时间、GPU/内存、队列、首 token、端到端 p50/p95、恢复演练 |

先建立 30–50 个工程任务用例和 100–200 题知识评测，再扩大独立评测集。训练/调优/测试严格区分；每次实验固定模型、prompt、检索、规则和数据版本。质量目标在基线后制定，不能把规划目标写成已达到指标。

必须覆盖：工具超时、模型非法调用、空检索、引用不存在、环境缺失、地块无权访问、取消后迟到结果、刷新、服务重启、重复审批、批次重复提交、数据库掉线和磁盘不足。输出标明部分完成，禁止失败后继续声称成功。

## 16. 核心演示与最终交付

演示流程：登录 → 选 A 区鸭梨 → 查看带来源的环境历史 → 上传病害图像 → 提问风险与采后方案 → 查看真实工具过程 → 打开证据与因果路径 → 比较两种干预 → 确认创建批次 → 查看数字身份证与风险继承 → 完整版展示路线/GIS 联动。

演示分为真实在线模式与明确标识的已保存记录回放。无模型/无网络时可回看结果，但不会将回放标记为新推理。设备模拟、定位模拟、模型实验指标各自标注。

最终交付包括源码与迁移、固定依赖和上游清单、模型/知识版本、Windows 启停与诊断、环境模板、演示数据与导入器、API/工具契约、评测脚本与原始结果、备份恢复说明、许可声明和更新后的技术报告。报告中的完成情况必须与软件实测相符。

## 17. 风险与待确认事项

| 项目 | 处理方式 |
|---|---|
| 上游 API 变化或耦合过深 | 固定 commit、适配层隔离、P0 决策和回归 |
| Qwen 工具调用或显存不足 | 本机实测、量化对照、限制上下文和并发 |
| 鸭梨真实数据不足 | 尽早采集与标注、冻结类别范围、保留拒识 |
| 缺少历史观测 | 新建采集链路、导入真实记录，演示来源明确 |
| 因果证据/专家资源不足 | 审核优先关键主链，区分相关和因果 |
| 多服务部署复杂 | Core/Full 配置、健康检查、离线包与恢复演练 |
| 目标过多 | 核心闭环先验收，再扩展空间与运输 |

执行前需明确比赛截止时间、团队投入、GPU 配置、现有图像/观测/农技资料、专家审核资源和是否接真实设备。这些影响规模与工期，不影响先完成源码验证、数据契约和核心任务原型。
