# 运输车到达与任务完成回报

## 平台行为

地图模拟到达规划终点后进入“等待车辆回报”，不再自动认定交付成功。该任务仍占用车辆调度位，不开始下一单，也不生成入库流水。

- 车辆 `ARRIVED`：确认任务目标点已到达。送货任务进入“等待卸货”，需人工确认卸货或等待车辆 `COMPLETED`；真实到达回报不会触发仿真的自动卸货。
- 车辆 `COMPLETED`：仅在**导航到达且卸货/交接完成**后发出。平台完成运输、写入交付时间并生成一次入库流水。不能只因定位到达就发此事件。
- 返回充电点的空载任务：`ARRIVED` 即确认该导航任务完成，不涉及库存。
- 同一 `messageId` 和相同内容的重传按幂等回报处理；相同编号改变内容会被拒绝。车辆、任务、目标站点、阶段、时间及任务状态均须匹配。急停、暂停、取消等状态下的新回报需先人工核验，不强制推进。

平台显示完成提示，在运输历史保留“车辆回报已确认”和回报时间。`simulate-arrival` 为显式的软件演示入口，界面显示“模拟车辆到达回报”，记录来源为 `SIMULATED`，不能作为真实车辆验收证据。现有地图和路径规划仍为软件仿真，新增接口不代表已经接上真实底盘导航。

## 串口报文

TY Serial v1 增加类型 **5（VEHICLE_EVENT）**，不改变帧头、序号、长度或 CRC。Python 与 C 编解码均已同步；老固件/网关需要更新后才支持类型 5。

```json
{
  "messageId": "persistent_event_uuid",
  "taskId": "平台下发的任务ID",
  "stopId": "warehouse",
  "phase": "DELIVERY",
  "event": "COMPLETED",
  "occurredAt": "2026-10-16T08:30:00Z"
}
```

车辆固定 ID 为 `cart-01`，`phase` 当前支持 `DELIVERY`（送货）和 `REPOSITION`（空载返航）。取货阶段仍沿用现有装货交接流程，不用送货完成事件替代装货确认。`stopId` 必须等于对应任务的目的地 ID；序号只用于串口回执关联，业务去重使用持久化 `messageId`。

在网关 devices 中绑定车辆串口地址：

```json
{"address": 5, "entityId": "cart-01", "role": "vehicle"}
```

网关不会对该设备轮询通用泵阀指令。只有绑定为 vehicle 的地址才接收车辆事件；事件与遥测一样先写 SQLite，再发 `scope=gateway_durable` 回执。此回执表示**网关已保存**，不表示平台已经完成任务。网关之后通过 HTTP 补传，HTTP 拒绝事件保存在 rejected 表，必须核验原因，不能丢弃后当作成功。

## 平台接口

`POST /api/farms/yantian-01/transport/vehicles/cart-01/events`，请求体为上述 JSON，需要现有平台 Bearer 令牌，网关自动调用该接口。JSON 回应为更新后的运输状态，包含任务的 `arrivalConfirmed`、`confirmationSource` 及 `vehicleReceipts`。

`POST /api/farms/yantian-01/transport/tasks/{id}/simulate-arrival` 仅允许当前软件状态中“等待车辆回报”的任务，显式产生模拟回报。

现有鉴权沿用平台网关令牌和串口地址绑定，并非车辆独立证书或加密串口身份。真实部署必须保证网关凭证、串口物理链路与导航程序可信。当前接口负责接收回报，未增加真实底盘的任务下发/运动控制驱动，需在对应车载导航软件中接入已有平台任务的 ID、目的地及阶段。

## 车载程序接入

`embedded/vehicle_signal.py` 的 `VehicleSignals.queue()` 是导航完成回调适配器；在**车载定位/对接确认**时调用 ARRIVED，在卸货或交付确认回调中调用 COMPLETED。不得由网页动画触发。

```python
from vehicle_signal import VehicleSignals

signals = VehicleSignals('/var/lib/agric/vehicle-events.sqlite', address=5)
# 以下参数来自当前已接受的运输任务，不自行编造任务ID。
signals.queue(task_id, destination_id, event='ARRIVED', phase='DELIVERY')
# 在车载串口通信循环中调用，port 为该程序独占的 pyserial 连接：
signals.exchange(port)
# 硬件确认卸货后：
signals.queue(task_id, destination_id, event='COMPLETED', phase='DELIVERY')
```

适配器持久化事件，同一任务/阶段/事件重试与重启保持相同 messageId 和原始时间；只有网关确认保存后才标为已交付网关。`exchange()` 应放在通信工作线程，不阻塞电机闭环或导航回调；同一 UART 不能由多个进程争抢读取。车载与网关间负责传输事件，平台库存和最终任务状态以平台 HTTP 应答为准。

独立联调命令（需要已存在、已装货且正在送货的任务，模拟端不会控制实体车辆）：

```bash
python embedded/vehicle_signal.py --port /dev/ttyUSB0 --address 5 \
  --task TASK_ID --stop warehouse --phase DELIVERY --event ARRIVED
```

自动化测试覆盖：地图到达不完成、车辆完成后只入库一次、到达与卸货区分、车辆/目标点不匹配拒绝、冲突重传拒绝，以及车端持久化→串口→网关落盘回执→断网补传。真实底盘、定位、对接传感器和卸货控制器仍需上车联调。
