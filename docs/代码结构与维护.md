# 代码结构与维护

本轮保留现有产品交互，将视觉推理与运行配置整理为独立边界，避免为了 Jetson 迁移改动业务含义。Java JAR 与前端静态文件跨架构交付，Node 和 Python 依赖在目标机安装，CUDA 引擎在板端构建。

| 目录或组件 | 负责内容 | 约束 |
| --- | --- | --- |
| frontend 和 landing | 数据工作台 Agent 3D 与官网 | GPU 推理配置留在服务器 |
| Java dashboard | 观测与演示设备动作 | 回执不代表硬件执行 |
| Java operations | 农事 生长 批次与回执 | 数据库为保存记录的来源 |
| Java agent | 鉴权 工具 任务 事件与结果核验 | 工具读取限于当前用户与基地 |
| agent-runtime | 官方 Harness 插件与模型适配 | 白名单工具 禁用 shell |
| Java vision | 上传 持久记录 复核与推理调度 | 有界队列 单工作进程 |
| PythonVisionRuntime | JSON 协议 超时与重启 | 不把模型文件载入 Java |
| vision-runtime/pipeline.py | 图像质量 预处理与 NMS | CPU 与 GPU 共用语义 |
| vision-runtime/backends.py | CPU 后端与显式选择 | 不静默伪装 GPU |
| vision-runtime/tensorrt_backend.py | TensorRT IO 和 CUDA 生命周期 | 固定形状 复用流与缓冲区 |
| deploy/jetson | 板端依赖 服务 密钥与验收 | 单独配置 不混入 Windows |

维护时先修改源码，再构建前端与 JAR，不手工编辑 static 中的编译产物。部署配置放入未跟踪的环境文件；模型权重和数据也不入 Git。发行脚本只复制明确列出的文件，不复制本机虚拟环境。

AgentRuntimeSettings 在启动时检查并发和预算；resource-limits.mjs 把同样的参数传给官方 SDK。Windows 默认两个执行线程和 8192 上下文，Jetson 默认一个线程和 4096 上下文，模型服务槽位与应用执行线程需要匹配。小上下文可能降低复杂多轮任务质量，使用实际工具调用流程验收。

AgentContextProjection 仅在短上下文 Harness 配置中去掉农场地图和 3D 几何信息，保留对象 ID、业务状态及指标；资料截为标注截断的 300 字来源片段。完整工具结果保存在审计事件中，批次核验继续使用原始业务事实，不对原记录做截断或修改。

视觉模型校验和会话初始化由常驻进程执行一次。每个请求带随机 ID，Java 验证响应 ID；EOF、超时和错误后销毁工作进程，下一次请求重建。进程存活与实际后端写入诊断和检测记录，便于识别启动失败。拒绝的图像仍通过原来的质量门控，不会为了加速跳过校验。

后端业务回归用独立测试库。Python 测试覆盖类别 NMS、模型输出格式、非法后端、同一常驻进程处理多张图和错误输入后的恢复。板端 benchmark 测暖机时延，validate_backend 测 CPU 与 GPU 数值差异；两者不能混作模型准确率评测。

现有 legacy Agent 引擎仅作兼容路径，Jetson 默认使用 Harness。旧登录与人脸云模块、程序化 3D 和演示数据初始化保留。没有删除用户数据或重写历史任务。正式产品的下一层整理应包含数据库迁移、角色授权、配置集中管理和持续集成；当前交付为可部署的展示版候选。
