# 盐田丰语软件演示交付

交付范围为单机软件演示：使用共享演示观测、模拟设备与用户登记记录，不要求真实传感器、实测 GIS 或真实生产数据。

## 操作入口

- 数据 → 业务接入：软件环境诊断，检查数据库、配置的 Agent 模型和本地梨叶模型。
- 种植 → 农事与采后追溯：登记农事、生长观察或采收批次；选择所属地块、填写说明。批次数量必须大于零。
- 批次“查看追溯”：按采收、分选、入库、出库顺序处理，每一步必须填写说明；完整轨迹保存，不能越级或重复提交。
- 设施、灌排、告警 → 执行与处置记录：查看自动保存的软件回执；刷新记录、按对象筛选或导出。
- 病虫害：图片上传、本机摄像头单帧/连续采样、本地推理、历史查询、候选检测框、人工复核和导出。人工意见单独保存，不覆盖原模型输出。
- Agent：保存任务核验流程、Harness 工具事件、结果与依据；取消、重新连接、失败/取消后重新执行，完成后继续追问并关联原任务，以及导出完整任务。重试新建任务并关联旧记录，不伪装为从中断的模型内部状态继续。
- 3D：植物园导览、地块与业务定位、自动巡场、桥面与地面漫游、碰撞约束、标签避让和画质选择。

农事与设备记录在登录用户之间共享；Agent 和视觉历史按用户隔离。业务记录以新增方式保留，批次流转使用版本约束避免并发重复处理。面板列表展示最新 200 个业务事件；指定批次追溯查询完整流转轨迹。Agent 查询最近 10 个批次和 20 个事件，长说明截取 200 字；批次概括遗漏时改用已保存事实摘要。默认软件操作参考资料只说明应用流程，不冒充农业生产规范。

## Windows 启动

双击 `start.cmd`。首次需要 JDK 17+、Node 24+、Docker Desktop 和 Ollama；脚本安装前端、Harness 和视觉依赖，构建并启动应用。`start.cmd -Task AgentSetup` 检查或启动本地 Ollama，缺少配置模型时下载；远程兼容模型按 `.env.local` 配置，不启动本地服务。

已有构建可使用 `start.cmd -SkipBuild`。`start.cmd -Check` 检查基础依赖与数据库，不要求关闭已运行的应用。`start.cmd -Task AgentSetup -CheckOnly` 检查模型就绪。

本机显存繁忙时运行 `start.cmd -Task AgentSetup -Cpu`，再设置 `AGENT_MODEL=agric-qwen2.5:7b-cpu`。CPU 配置共享原 Qwen2.5 7B 权重，无需再次下载；本机验收使用该配置。任务预算默认 600 秒，可用 AGENT_TIMEOUT_SECONDS 在 60–900 秒内设置。

## 发行包

`mvnw.cmd package` 生成可运行 JAR；`start.cmd -Task Release` 将它与 Harness、ONNX 模型、启动和备份脚本打包到 target/release-时间.zip。解压后解压后运行发行包内的 `start.cmd`，无需源码构建或 Maven。首次运行安装 Node/Python 依赖；仍需 Java 17+、Node 24+、Python 3.11、Docker Desktop 和 Ollama。发行包不包含用户数据、密码和私有配置。

## 备份与恢复

运行 `start.cmd -Task Backup`，生成 `backups/` 下带 SHA-256 清单的 ZIP，包含数据库和视觉原图。模型权重、依赖、密码和环境配置不打包。正式备份前暂停写入操作，确保数据库与文件快照一致。

恢复到新的空数据库：

```powershell
.\start.cmd -Task Restore -BackupFile 'D:\Code\agric\backups\你的备份.zip' -TargetDatabase tianyan_restored
```

脚本验证清单与文件哈希；拒绝覆盖非空数据库及已有视觉目录。恢复后停止应用，将 `.env.local` 的 DB_NAME/DB_URL、VISION_STORAGE 设置为脚本输出的位置，然后重新启动。原数据库和文件不受影响。备份/恢复中间文件在 `target/` 和容器 `/tmp/` 保留，便于失败诊断，可在确认成功后清理。

## 验证范围

后端测试使用独立 `tianyan_test`，不修改演示库。验证包括批次顺序与跨基地限制、农事与生长记录、灌排回执和告警恢复、视觉用户隔离与复核、Agent 事件持久化和取消保护。浏览器验证包括实际业务登记/完整流转/刷新持久化、手机布局、摄像头模拟视频输入执行真实 ONNX 推理，以及后台释放摄像头。备份已实际恢复到独立验证数据库。

本地模型需要相应计算资源。当前视觉模型输出梨叶候选症状，不能声称经过鸭梨独立诊断验证。3D 保持程序化园景风格，概念坐标服务于软件展示。

## 本轮验收结果

26 项后端测试覆盖身份、观测、业务流转、Agent 和视觉；另有 2 项官方 Harness 插件测试。桌面和手机实际操作验证了六个统一侧栏、完整批次流程、持久保存、视觉复核、任务追问与取消、完整记录导出和 3D 漫游。模拟摄像头输入完成真实 ONNX 推理，未使用实体摄像头。

Qwen2.5 7B CPU 配置下，官方 Harness 实际读取业务与农场、检索软件操作参考并完成批次回答。显式分类后的回答正确识别已出库批次；额外事实校验处理标题、编号或状态遗漏。

备份实际恢复到独立验证库；拒绝覆盖非空库、拒绝校验损坏的备份。Windows 前置检查与当前环境启动通过；不把当前机器验证表述为所有 Windows 设备或干净虚拟机均已验证。

发行入口已使用 Windows PowerShell 5.1 在独立 8082 端口、恢复后的验证库实际启动；首次安装 Harness 与视觉依赖成功，页面与受保护状态接口返回 200。已修复旧版 PowerShell 的 Node 参数引号与 UTF-8 模型清单读取问题；重复启动会重新检查视觉依赖，支持首次安装中断后重试。当前主应用继续运行在 8081。
